## Домен — дерево задач

- Роль агента: обслуживает дерево задач, исполняя запросы пользователя; сам ничего не планирует [решено]
- Роль агента → Запрос пользователя → найти соответствующий узел [концепция/факт]
- Роль агента → Собрать контекст из узла и близлежащих узлов [концепция/факт]
- Роль агента → Исполнить запрос мутацией дерева [концепция/факт]
- Схема хранения [концепция/факт]
- Схема хранения → Плоский список узлов с полем parent; children не хранится — индекс [концепция/факт]
- Схема хранения → Лог JSONL мутаций — истина [концепция/факт]
- Схема хранения → Проекция в памяти: Map⟨id,node⟩ + Map⟨parent,id[]⟩, реплей при старте [концепция/факт]
- Схема хранения → Снапшот на диске + хвост лога для восстановления [концепция/факт]
- Схема хранения → Вложенный JSON-объект дерева [отклонено] — примечание: перемещение = переписывание поддеревьев
- Схема хранения → Materialized path / depth в узле [отклонено] — примечание: денормализация, чинить при каждом move
- Схема хранения → Дерево целиком в текстовом файле, модель выдаёт патчи [отклонено] — примечание: та же проблема, что у вложенного JSON — правка переписывает поддерево
- Сборка контекста узла [концепция/факт]
- Сборка контекста узла → Предки — по parent до корня («где я нахожусь») [концепция/факт]
- Сборка контекста узла → Дети — childrenIndex [концепция/факт]
- Сборка контекста узла → Блокеры — blocks + обратный индекс [концепция/факт]
- Сборка контекста узла → Сёстры — дети родителя [концепция/факт]
- Сборка контекста узла → Рендер в markdown, не JSON; ~1–2k токенов на узел [концепция/факт]
- Сборка контекста узла → Как подцепить ветку родителей к семантически найденному узлу? [открытый вопрос] — примечание: вниз по вложенности работает, вверх — нет
- Мутации [решено]
- Мутации → Агент не пишет в хранилище — возвращает типизированную команду [концепция/факт] — примечание: move · set_status · rename · create
- Мутации → Валидатор перед логом; проверка цикла при move обязательна [концепция/факт]
- Мутации → Inbox как служебный элемент [концепция/факт]

## Жизненный цикл задач и гейты

- Статусная модель [решено]
- Статусная модель → open · done→closed · archive→superseded · focus · pause [концепция/факт]
- Статусная модель → focus и pause — нативные статусы, ставит только пользователь [концепция/факт]

- Агент в приложении не участвует — задач не берёт [концепция/факт]
- focus/pause на агентов не влияют — это вид пользователя [концепция/факт]

- Гейты → Гейт = задача с исполнителем = user [концепция/факт]
